# Как работает подбор

## Данные и матрицы

В `data/products.csv` хранится каталог, в `data/ratings.csv` — оценки от 1 до 5. Одна строка означает оценку одного товара одним пользователем. Матрица предпочтений строится в оперативной памяти в разреженном формате CSR: строки — пользователи, столбцы — товары, отсутствие записи означает отсутствие оценки. Для каждого запуска матрица пересчитывается.

Плотная матрица сходства пользователей также хранится в оперативной памяти. Это приемлемо для демонстрации, но её память и время растут квадратично с числом пользователей. Набор проекта учебный, а не промышленный.

## Сходство

Для каждого пользователя `u` рассчитывается средняя `mean_u` по всем его оценкам. Для пары пользователей используются **только совместно оценённые товары**: из каждой оценки вычитается средняя оценка её автора, затем для двух полученных векторов рассчитывается косинусное сходство. Это центрированное косинусное сходство; оно может быть положительным или отрицательным. Если норма одного из векторов равна нулю, сходство принимается равным нулю.

Сходство умножается на `(n - 1) / (n - 1 + 3)`, где `n` — число общих оценённых товаров. При одной общей оценке коэффициент равен нулю: таких данных недостаточно для сравнения. Сам пользователь не считается своим соседом. Для прогноза используются только соседи с положительным сходством.

## Прогноз

Для известного пользователя и товара базовый прогноз — средний рейтинг товара плюс сглаженная индивидуальная поправка: `(mean_u - global_mean) * count_u / (count_u + 5)`. Здесь `global_mean` — средняя всех обучающих оценок, `count_u` — число оценок пользователя. Если оценок товара нет, вместо среднего по товару используется среднее по каталогу.

Из пользователей, оценивших конкретный товар, выбираются до пяти наиболее похожих. Их взвешенные отклонения оценок от собственных средних добавляются к базовому прогнозу; сумма весов сглаживается добавлением 1 в знаменателе. Если соседей нет, используется только базовый прогноз. Результат ограничивается диапазоном 1–5.

Значения сглаживания 3, 5 и 1 — параметры учебного алгоритма, а не универсальные константы. Они выбраны для уменьшения влияния небольшого числа оценок и проверены на искусственных данных. Эксперимент не доказывает оптимальности этих значений.

Новый пользователь без оценок получает товары по среднему рейтингу, при равенстве — по количеству оценок и идентификатору. Для товара без оценок используется среднее по каталогу, либо 3, если оценок вообще нет. Уже оценённые товары исключаются. Фильтры категории и цены применяются до сортировки; одинаковые прогнозы упорядочиваются по идентификатору.

## Проверка

Команда `python evaluate.py` делит исходный демонстрационный набор на обучение и проверку, скрывая примерно 20% оценок каждого пользователя, у которого есть как минимум две. Прогнозы и средние базовой модели вычисляются только по обучающей части. Команды для сравнения на большем искусственном наборе:

```bash
python evaluate.py --ratings data/experiment/ratings_synthetic.csv --seed 100 --model legacy --ranking
python evaluate.py --ratings data/experiment/ratings_synthetic.csv --seed 100 --model current --ranking
```

`legacy` воспроизводит прежнюю логику и доступен только для экспериментов. При `--ranking` оценивается, попал ли хотя бы один из отложенных товаров с оценкой 4–5 в первую тройку; рассматриваются только пользователи с такими отложенными оценками. Неизвестные оценки не считаются отрицательными, но выбор оценённых товаров смещён, поэтому эта метрика — лишь приближение, а не проверка удовлетворённости пользователя.

Разбиения пересекаются; это измерения на одних и тех же пользователях, а не независимые эксперименты. Синтетические оценки созданы по заданным предположениям о предпочтениях и могут благоприятствовать отдельным подходам. Нужны данные реальных пользователей и отдельный отложенный набор, чтобы делать выводы о качестве в действительности.
